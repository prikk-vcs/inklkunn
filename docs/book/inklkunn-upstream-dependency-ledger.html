inklkunn

inklkunn — Upstream Dependency Ledger
DocumentA living record of every behaviour of prikk, planeter and wiki-commons that inklkunn’s design or code relies on, and how sure we are of each.
Versionv1.0 (2026-10-27 — seeded during M0 from the design set’s UD-1 … UD-10 and from what T1–T6 measured on prikk 0.54.1 / release asset 0.54.0, planeter 0.4.0 and wiki-commons commit 19f021c6)
WhyA wiki engine whose storage is a pre-1.0 VCS cannot afford an unverified assumption: planeter was burned once by one (its “seal locally, the forge’s ref advances” fallback, measured false). Every dependency is named here with its evidence, so a wrong one is caught before it is built on, and so a new reader sees what is real, what is ruled, what is not shipped, and what is still assumed.
How to useBefore implementing an RFC, check its rows here (the RFC names them). When an upstream ships, rules or answers, move the row’s status and cite the evidence; the version line names the release or the letter. An ASSUMED row implemented without promotion to CONFIRMED is a risk taken knowingly, and the review request says so.
BasisRFC 010 D-7; requirements §15 (UD-1 … UD-10); planeter’s prikk dependency ledger (the shape, and its measured facts carried in as PL- rows where inklkunn reuses them)

Status legend

  • CONFIRMED — measured here, on a named binary or commit (the evidence column says which).
  • RULED — the upstream owner’s or architect’s word, or an accepted upstream RFC, cited.
  • GATED — accepted or proposed upstream, not shipped; inklkunn designs to it and gates the code on the binary.
  • ASSUMED — relied on, not yet verified: the live risk list.
  • PARTIAL — partly confirmed; a named gap remains.

PK-9A process under RLIMIT_DATA dies in one of four shapes: Rust abort (134/SIGABRT, “memory allocation of … failed”), loader exit 127 (“Cannot allocate memory”, “cannot allocate TLS data structures”), a bare SIGSEGV before any message (GitHub’s ubuntu-24.04 runner), or verify exit 1 “did not complete every stage”CONFIRMED (0.54.0 release asset and 0.54.1, 2026-10-27)the driver reads any of them, and under a ceiling any death by signal, as CeilingExceeded, never as a verdict. 64 KiB fails in the loader; 256 KiB runs verify on a 60 KB repository.
PK-10The 0.54.0 release asset prikk-x86_64-unknown-linux-gnu.tar.gz is a dynamically linked glibc PIE (ld-linux-x86-64.so.2), so the sandbox must bind /usr and the usr-merge symlinksCONFIRMED (asset downloaded 2026-10-27)the Dockerfile and the sandbox vector assume glibc; a musl asset would change nothing but the bind list could shrink.
PK-11A repository path (worktree-relative, in bytes) may not exceed 1024 bytes (“invalid name: repository path exceeds 1024 bytes”)CONFIRMED (0.54.1, spike A generator)bounds the hierarchy depth: with one-character components about 500 levels under pages/. title_to_path must refuse or the proposal must be refused before commit (RFC 004 handoff: a check against this limit, surfaced as a lint before it is a refusal). The requirements’ “depth 1,000” measurement target is unattainable; spike A measured depth 500.
