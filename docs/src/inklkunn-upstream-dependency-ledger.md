## Status legend

- **CONFIRMED** — measured here, on a named binary or commit (the evidence column says which).
- **RULED** — the upstream owner's or architect's word, or an accepted upstream RFC, cited.
- **GATED** — accepted or proposed upstream, **not shipped**; inklkunn designs to it and gates the code on the binary.
- **ASSUMED** — relied on, not yet verified: the live risk list.
- **PARTIAL** — partly confirmed; a named gap remains.

Raised to the architect in the handoff's review request; **a candidate for the next bundled upstream letter** (the owner bears the cost of each). **Architect, 2026-10-29:** reproduced on 0.54.1; prikk's reference documents `trust maintainer remove` as **revocation** and key rotation as "not built yet, not refused" (`trust-threat-model.md`), so this is a stated rule; the owner decides the default (DR-10); a rotation that keeps history verifiable is asked in the draft letter of 2026-10-29. **prikk, reply of 2026-10-29 (0.55.0, unchanged here):** all three readings confirmed — revocation judges the whole history against today's trust set by design; keep-the-old-key is the correct rotation and no mechanism was missed (the format has carried several signatures per object since 0.45.0, the base a future re-attestation would build on, but nothing uses it for this); a leaked still-trusted key can do everything it is trusted for (seal blocks, publish ref states and updates, sign tags), and while each block names its signer, a copy **cannot prove** a block came after the successor's adoption, which is local.
